Deployment

One WAR. All environments.

Pulse Monitor ships as a single pulseMonitor.war built with Maven. A WebLogic deployment plan and environment-specific properties files handle context root overrides and credentials — no code changes between environments.

Build once with the correct Maven profile, then deploy using WebLogic Deployer with the matching plan variables file.

# Build and deploy to UAT
mvn clean package -P uat
java weblogic.Deployer \
  -adminurl t3://uat-host:7001 \
  -name pulseMonitor \
  -source target/pulseMonitor.war \
  -variables deployment/plan-variables-uat.properties \
  -deploy
Local / Dev
mvn -P local
Development mode. JSF project stage set to Development. Local weblogic-local.properties.
SIT
mvn -P sit
System integration testing environment. Packaged with weblogic-sit.properties.
UAT
mvn -P uat
User acceptance testing. Packaged with weblogic-uat.properties.
PROD
mvn -P prod
Production. Secure cookies enforced. weblogic-prod.properties with secrets injected at deploy time.

Security model

Layered request hardening out of the box

LAYER 1 — TRANSPORT

TlsEnforcementFilter + SecurityHeadersFilter

HSTS, browser security headers, and TLS-only traffic. Controlled per environment via pulse.security.* flags in the properties file.

LAYER 2 — AUTHENTICATION

Session management + PageFlowFilter

Flow token issued at POST /flow/token. PageFlowFilter enforces token for all authenticated GET navigation and AJAX patterns.

LAYER 3 — AUTHORISATION

MenuAuthorizationFilter + PulseMenuPathAuthorization

Path-to-menu RBAC mapping. Users see only navigation entries they are authorised to access. Menu search respects the same allowedMenus set.

LAYER 4 — REQUEST INTEGRITY

CsrfFilter + pulse-security-nav.js

Synchronizer token validation on all mutating requests. Client-side JS injects X-CSRF-Token, X-Pulse-Flow-Token, and X-Requested-With automatically.

LAYER 5 — RATE LIMITING

RateLimitFilter

Protects all endpoints from excessive request volumes. Configurable per endpoint pattern.
