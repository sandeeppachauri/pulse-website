Server Health Dashboard

Real-timeMulti-cluster30s refresh

See every node, at a glance, right now

Your operations team should never have to log into the WebLogic console just to find out if a server is healthy. The Pulse Monitor live dashboard aggregates memory usage, heap pressure, thread activity, and request throughput for every node in your cluster — updated every 30 seconds.

When a node starts struggling, the dashboard flags it immediately. Select any server from the list to see its full metric breakdown, 24-hour request traffic chart coloured by peak and off-peak windows, and endpoint performance data from automated log analysis.

Live KPI strip
Total servers, active nodes, average RAM, heap pressure, stuck threads, and requests per hour — all on one screen.
Node resource table
Per-node RAM bars, heap used vs free, stuck thread count, and active request count across every server.
24-hour traffic chart
Peak vs off-peak request traffic per server — coloured by business hours windows so patterns are obvious.
Metric history
Every snapshot is saved so your team can query historical health data when an incident needs a post-mortem.

Message Queue Monitoring

JMS queuesBacklog alertsMessage detail

Stop JMS backlogs before they become business incidents

Message queue backlogs are one of the most common causes of silent failures in Oracle middleware. A queue accumulates messages, no one notices, and eventually a downstream business process stalls. Pulse Monitor gives your team continuous visibility into every JMS queue — depth, consumer counts, and throughput — without writing scripts or logging into the admin console.

Configurable backlog thresholds trigger alerts the moment a queue starts accumulating messages beyond normal levels, long before the business notices anything is wrong.

Queue depth tracking
Live depth, consumer count, and pending messages for every JMS queue across all servers — constantly refreshed.
Backlog alerts
Set per-queue thresholds. Get notified the moment a queue backs up beyond acceptable levels.
Dashboard notifications
JMS-delivered alerts appear in the dashboard notification panel including message content and timestamp.
Message browse & detail
Inspect individual JMS messages directly from the dashboard — body, headers, and metadata without any tooling.

Understand your API landscape before making changes

Modern Oracle middleware environments are webs of interconnected services. When you change or decommission an API, do you know every service that depends on it? Pulse Monitor maintains a Swagger-backed API catalog with full dependency hierarchy — so your team understands downstream impact before any change reaches production.

Automated reachability checks ping every registered endpoint on a schedule and surface failures in the dashboard immediately. No more discovering broken integrations after a deployment.

Swagger API hub

Dependency hierarchy
Visual map of which services consume which APIs — know the blast radius of any change before you make it.
Reachability monitoring
Scheduled pings verify every API endpoint. Unreachable APIs are flagged in the dashboard the moment they go down.
Dependency detail
Drill into any API to see all dependents, latest reachability status, and linked Swagger documentation.

Alerts & Notifications

ConfigurableJMS deliveryAlert history

Get notified before users raise a ticket

Every significant operational event — stuck threads, JDBC pool pressure, JMS backlog, certificate expiry, composite faults, unreachable APIs — can be configured as a Pulse alert. Define the threshold, assign the severity, and Pulse handles delivery via JMS to your operations team in real time.

Alert history is stored and searchable. Your team can filter by system, date range, and severity to understand patterns and improve response over time — not just react to individual events.

Stuck threads & node faults
Fires immediately when thread counts or node states cross configured thresholds on any cluster node.
JDBC pool pressure
Alert when a connection pool usage exceeds your threshold — before requests start queuing and timing out.
JMS queue backlog
Catch message accumulation the moment a queue depth crosses its threshold — before business processes stall.
Certificate expiry
Automated warning when any certificate is within 15 days of expiry — across all environments and trust stores.
Composite fault threshold
SOA composite fault count exceeded — know the moment a service starts degrading, not after users complain.
Unreachable API
A registered endpoint failed its reachability check — immediate notification to the team via the dashboard panel.

Log analysis in Oracle middleware is typically manual and time-consuming — log into the server, find the right file, search for errors, correlate across nodes. Scheduled log ingestion

AI pattern detection

Certificate Tracker

Auto-scan15-day warningAll environments

Expired certificates cause outages. Pulse stops that.

Expired SSL/TLS certificates are one of the most avoidable causes of production incidents — yet they still happen because tracking them manually across multiple trust stores and environments is tedious and easy to forget. Pulse Monitor automates the entire process.

The scheduler scans every configured trust store path across all registered environments and records each certificate's expiry date. Certificates expiring within 15 days appear as a KPI badge on the main dashboard — your team sees the warning the moment they log in, every single day.

Automated trust store scan
Scheduler scans all configured trust store paths — no manual checking, no spreadsheet tracking required.
15-day dashboard warning
KPI badge on the main dashboard highlights certs expiring within 15 days — impossible to overlook.
Full certificate table
Browse every certificate across every environment — system, trust store path, alias, expiry date, and days remaining.
Alert integration
Certificate expiry alerts feed into the same Pulse notification system — one consistent place for all team alerts.
